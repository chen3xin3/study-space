# 学习空间开源副本设计

## 目标

在 `D:\Desktop\app\开源` 中生成一份可独立发布的“学习空间”源码副本，保留当前工作区的最新功能，但不继承原项目的 Git 历史，不改动或覆盖原项目中的任何文件。

## 仓库结构

- 开源副本自己拥有 `.git` 目录和 `main` 分支。
- 保留前端、Tauri/Rust 后端、Windows 与 Android 配置、测试、应用图标和教程。
- 顶层提供面向公开用户的 README、MIT 许可证、贡献说明、安全说明、行为准则和变更记录。
- `.github` 中提供问题模板、依赖更新配置和 Windows/Node.js 自动检查。

## 公开边界

复制源码时排除：

- 原项目 `.git` 历史、开源输出目录本身以及本地工作辅助目录。
- `node_modules`、`dist`、`target`、`src-tauri/gen`、`.vite`等可重建内容。
- `release`、`artifacts`、`.visual-qa`、`.android-tools` 及下载的 SDK/JDK/安装包。
- `.env*`、数据库文件、日志、密钥、证书和 Obsidian 工作区状态。

## 元数据和隐私

- 公开名称统一为“学习空间”，仓库名为 `study-space`。
- `package.json` 保留 `private: true`，防止误发布到 npm；同时补充项目描述、MIT 许可证和 GitHub 地址。
- 教程中的本机绝对路径改为通用示例，不公开本地用户名、个人配置、数据和凭证。
- AI 功能只保留接口与本地安全存储机制，不包含真实 API 密钥。

## 验证和发布

1. 对公开副本执行凭证、大文件和意外产物扫描。
2. 执行 `npm ci`、`npm run test:run`、`npm run build`、Rust 测试和检查。
3. 检查 Git 状态和差异，确认没有引入原项目的生成内容或私密信息。
4. 初始提交后连接 `https://github.com/chengxin23333-hue/study-space.git`。
5. 先推送到当前私有仓库检查，确认无误后再由仓库所有者切换为公开。

## 成功标准

- 原项目不受影响，所有未提交修改仍原样保留。
- 开源目录可单独安装依赖、测试和构建。
- 新仓库仅有干净的公开历史，不含旧安装包、浏览器缓存、个人数据或真实凭证。
- GitHub 首页能清楚说明项目用途、运行方式、测试方式和参与贡献方式。
