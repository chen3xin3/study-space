# 第 38 章：英语资料模块

## 本章目标

理解英语页面作为资料入口的职责，追踪单词照片、作文原稿、试卷照片、资料库、识别草稿和人工确认的完整流程。

## 开始前需要会什么

完成资料与照片章节，理解附件、草稿、服务边界和人工确认。

## 新术语表

| 术语 | 含义 |
|---|---|
| Import draft | 识别后、确认前的临时结果 |
| Source image | 用户保存的原始照片 |
| Recognition | 从图片提取结构化文字 |
| Review screen | 用户核对并修改结果的页面 |
| Provenance | 资料来自哪张原图、哪次识别 |

## 先建立直觉

英语模块不是背单词游戏，而是英语资料工作台：把纸上的单词、作文和试卷收进来，保留原图，识别后由人核对，再进入可搜索的资料库。

## 图解

~~~mermaid
flowchart LR
  A[拍照/选择图片] --> B[保存原图附件]
  B --> C[创建导入草稿]
  C --> D[OCR/AI 识别]
  D --> E[人工核对]
  E --> F[单词资料库]
  E --> G[作文资料库]
  B --> H[按日期查看原始照片]
~~~

## 跟我一步一步做

1. 从 [EnglishDashboard](../../../src/pages/english/EnglishDashboard.tsx) 识别五个真实入口：单词导入、作文导入、单词库、作文库、原始照片。
2. 打开 [VocabularyImportPage](../../../src/pages/english/VocabularyImportPage.tsx)，记录文件选择、识别、保存草稿和跳转步骤。
3. 在 [VocabularyImportReviewPage](../../../src/pages/english/VocabularyImportReviewPage.tsx) 找人工核对字段，不让识别结果直接污染正式资料。
4. 对作文重复同样追踪：[EssayImportPage](../../../src/pages/english/EssayImportPage.tsx) → 编辑/尝试记录 → 作文资料库。
5. 阅读 [WordLibraryPage](../../../src/pages/english/WordLibraryPage.tsx) 和 [EssayLibraryPage](../../../src/pages/english/EssayLibraryPage.tsx)，确认列表承担“找资料”，不是塞入所有编辑功能。
6. 原图统一进入照片归档，按日期与 subject=english 查找。
7. 为导入失败、部分识别、重复提交、页面重开和撤销保存设计状态。

## 完整示例

导入一张作文照片时，系统先复制原图并得到 attachmentId；创建 import draft；识别标题、正文和可选翻译；核对页面让用户修改；确认后创建作文或作文尝试，并保留附件关联。任何识别建议都不应覆盖原始照片。

## 逐段解释

原图是最可靠证据，识别文字是可修改派生结果。草稿隔离不确定结果，人工确认是进入正式库的边界。单词照片和作文照片共享附件能力，但业务字段不同，因此共享底层文件服务而不是强行共用一个巨大页面。

## 运行并观察

运行英语仪表盘、单词导入、核对、单词库、作文导入和作文库测试。使用测试图片走一遍流程，检查返回后草稿是否仍在、确认后是否能从资料库与照片归档分别找到结构化资料和原图。

## 常见错误与修复

- 识别成功就直接保存正式资料：增加核对草稿。
- 只保存识别文字：原图丢失后无法复查。
- 把英语页面做成背词页：保持资料库定位。
- 导入按钮重复点击产生两份：使用 requestId 或保存中状态实现幂等。
- 页面把 OCR、存储和数据库全写在一起：通过服务分层。

## 必做练习

画出单词导入时序图；列出原图与识别文字各自字段；设计识别半失败界面；说明确认按钮为何是数据边界。

## 选做挑战

设计“试卷资料库”：保留整张试卷、拆分题目区域、关联错题与笔记，但第一版不自动裁切，先保证人工分类可用。

## 答案与思路

时序必须含附件、草稿、识别、核对、正式记录；原图保存哈希与路径，文字保存结构化字段和来源；半失败可保留已识别内容并允许重试；确认后才允许进入搜索、统计和后续 AI。
