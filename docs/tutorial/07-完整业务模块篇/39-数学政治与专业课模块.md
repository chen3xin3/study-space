# 第 39 章：数学、政治与专业课模块

## 本章目标

学习如何让三个学科共享资料能力但拥有不同的信息结构、入口和视觉语言，并避免复制三套业务代码。

## 开始前需要会什么

理解配置驱动界面、组合组件、资料模型与路由。

## 新术语表

| 术语 | 含义 |
|---|---|
| Configuration driven | 用配置描述差异，由组件负责渲染 |
| Composition | 用小组件组合页面 |
| Subject identity | 学科特有的内容重点和视觉识别 |
| Bento grid | 不同尺寸卡片组成的网格 |
| Shared capability | 多学科共同使用的底层功能 |

## 先建立直觉

“统一”不是三个页面长得完全一样，“独特”也不是三份复制代码。资料保存、路由和卡片行为可以共享；数学突出错题与演算，政治突出时政和背诵，专业课突出章节、教材和真题。

## 跟我一步一步做

1. 打开 [SubjectPage](../../../src/pages/subjects/SubjectPage.tsx)，看 subject id 如何选择配置；英语为何走独立页面。
2. 阅读 [subject-config](../../../src/components/subjects/subject-config.ts)，把标题、说明、主入口、卡片和 artDirection 分开记录。
3. 阅读 [SubjectHero](../../../src/components/subjects/SubjectHero.tsx) 与 [SubjectBentoGrid](../../../src/components/subjects/SubjectBentoGrid.tsx)，观察共享结构如何消费配置。
4. 数学入口围绕录入错题、错题库、笔记例题和模拟考试；视觉可使用几何、坐标和低饱和暖冷对比，但不能牺牲阅读。
5. 政治入口突出考点、时政、背诵和练习；编辑部式排版可以有识别度，但减少无用英文装饰。
6. 专业课围绕教材章节、真题、笔记和资料；书架或索引感可以帮助理解层级，但卡片仍需清楚可点。
7. 在 1024×768 与 800×1280 检查网格重排、文字换行、触控面积和无横向滚动。

## 完整示例

~~~ts
type SubjectConfig = {
  title: string;
  description: string;
  artDirection: "geometry" | "newsroom" | "bookshelf";
  primaryAction: SubjectAction;
  actions: SubjectAction[];
};
~~~

一个 SubjectPage 读取不同配置即可生成三种页面；真实业务入口仍指向各自路由。

## 逐段解释

视觉主题应服务内容模型：数学的网格表达问题分类，政治的栏目表达材料与考点，专业课的层级表达教材章节。共享组件统一可访问性、路由和响应式；配置保留学科差异。若某学科出现真正不同的复杂流程，再拆专用组件。

## 运行并观察

运行 SubjectPage 与配置测试，依次打开数学、政治和专业课。检查所有功能入口能导航，键盘焦点清晰，卡片不是仅靠 hover 可用，窄屏不遮挡文字。

## 常见错误与修复

- 三页复制粘贴：抽共享结构和配置。
- 所有页面换个颜色就算特色：从学科任务和信息层级设计构图。
- 背景过深、发光太强：让内容面保持高对比和低饱和。
- 装饰挡住触控：装饰层 pointer-events:none。
- 配置包含业务执行代码：配置描述内容，服务执行业务。

## 必做练习

给三学科分别写一句页面目标；列出共享字段和独有字段；画出平板单列顺序；为每个真实入口写一条路由测试。

## 选做挑战

增加主题预览页，同时展示三种 artDirection，并用相同假数据验证结构一致、视觉不同、触控和对比度合格。

## 答案与思路

目标应围绕学习行为而非形容词；共享字段含标题、路由、图标和说明，独有字段来自业务；窄屏先主入口再高频工具；路由测试检查可访问名称和目标路径。
