# 第 37 章：首页、统计与复习闭环

## 本章目标

把教学版的待办、专注记录、日历与趋势映射到真实项目，理解“计划 → 学习 → 记录 → 统计 → 安排复习”的闭环。

## 开始前需要会什么

完成第 33、35 章，理解服务接口、时间范围、版本号和派生统计。

## 新术语表

| 术语 | 含义 |
|---|---|
| Dashboard summary | 首页一次加载需要的聚合数据 |
| Local day window | 本地自然日在 UTC 中的开始与结束 |
| Aggregate | 把多条记录汇总成总数或趋势 |
| Review queue | 按规则选出的待复习资料 |
| Closed loop | 行动结果能影响下一次计划 |

## 先建立直觉

统计不是漂亮图表，而是帮助下一步决策。首页安排任务，专注页产生有效学习时间，统计页识别薄弱学科，复习队列再把需要巩固的资料推回今日任务。

## 图解

~~~mermaid
flowchart LR
  A[今日任务] --> B[专注学习]
  B --> C[专注记录]
  C --> D[日历与趋势]
  D --> E[发现薄弱点]
  E --> F[复习队列]
  F --> A
~~~

## 完整示例

一次闭环可描述为：创建“复习高数极限”任务 → 完成 40 分钟专注 → 保存科目和中断 → 首页日历增加学习时间 → 周统计显示数学投入 → 掌握度低的极限错题进入复习队列 → 用户把它加入明日任务。

## 逐段解释

自然日不能简单用 UTC 日期切割，中国凌晨的记录在 UTC 仍可能属于前一天。前端计算本地日窗口，后端按明确边界查询。统计模型应由纯函数生成，页面只负责展示；这样零数据、跨日和范围切换都可测试。

## 运行并观察

运行首页、统计页和专注相关测试。手动创建任务并完成一轮专注，切换今天、最近七天和月视图，确认同一记录只统计一次，休息不进入总时长。

## 常见错误与修复

- 直接按 UTC 日期分组：使用本地日窗口。
- 图表组件自己请求数据：让页面或服务统一加载。
- 空数据当错误：展示清楚的零状态。
- 同时统计运行中区间和已结算时间：明确单一计算公式。
- 推荐复习没有理由：保存来源、掌握度和上次复习时间。

## 必做练习

画出一次任务完成到统计更新的调用链；设计跨午夜测试；解释零数据和加载失败的区别；列出一个可解释的复习优先级公式。

## 选做挑战

实现“从统计卡片创建复习任务”的设计稿与接口草案，要求可撤销、不会重复创建，并显示推荐理由。

## 答案与思路

调用链应跨页面、服务、command、仓储和 SQLite；跨午夜用固定时区边界测试；零数据是成功结果，失败是请求没有可信结果；优先级可组合低掌握度、距上次复习天数和错题次数。
