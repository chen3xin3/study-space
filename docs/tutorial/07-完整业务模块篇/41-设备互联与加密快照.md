# 第 41 章：设备互联与加密快照

> 当前仓库保存了完整设计和实施计划，但在两个方向都没有完成真机验收前，不能宣称“双端互联已经打通”。

## 本章目标

理解整库快照同步、一次性配对、局域网传输、完整性校验、敏感数据排除、接收端保护备份和失败回滚，并能制定真实双端验收方案。

## 开始前需要会什么

完成附件、备份、Tauri command、服务接口和安全密钥章节；知道数据库事务不能自动回滚文件。

## 新术语表

| 术语 | 含义 |
|---|---|
| Snapshot sync | 把完整数据快照传给另一台设备 |
| Pairing code | 短时、一次性的连接验证码 |
| Manifest | 快照版本、大小、文件和哈希清单 |
| Protection backup | 覆盖前保存接收端现有数据 |
| Rollback | 恢复失败后退回原数据 |
| Merge sync | 逐条比较两端记录，首版不做 |

## 先建立直觉

首版互联像“把电脑上的整只保险箱搬到平板”，不是把两边抽屉逐个合并。因此方向和替换影响必须醒目：电脑 → 平板会替换平板当前数据。可靠性比自动化更重要。

## 图解

~~~mermaid
sequenceDiagram
  participant S as 发送端
  participant R as 接收端
  S->>S: 创建完整备份快照
  R->>S: 地址 + 一次性配对码
  S-->>R: manifest 摘要
  R->>R: 用户确认替换方向
  S-->>R: 流式传输快照
  R->>R: 大小+哈希+ZIP路径检查
  R->>R: 创建本机保护备份
  R->>R: 恢复或回滚
  R->>S: complete 并关闭会话
~~~

## 跟我一步一步做

1. 先根据本章“本章目标”和“先建立整体地图”写清包含与不包含的范围。
2. 首版只在同一局域网、用户主动开启、短时监听；不做云账户、后台自动同步或逐条合并。
3. 发送端复用现有备份格式，生成不含 AI API Key 的临时快照。
4. 配对码由安全随机数产生、十分钟过期、限制错误次数、成功后不可重复使用。
5. 未认证请求不能得到设备名称、快照摘要或文件长度。
6. 接收端先读取 manifest，不立即下载；页面显示来源、版本、时间、大小、附件数和方向。
7. 下载设置连接超时、读取超时、总字节上限，边写 .part 文件边计算 SHA-256。
8. 长度和哈希一致后才能检查快照；网络模块不能直接替换数据库。
9. 恢复前建立保护备份；失败必须保留或回滚原数据库和附件。
10. 完成、停止、过期或失败时关闭监听并清理临时资源。
11. 浏览器预览明确提示不支持，不能伪造连接成功。
12. 最后用真实 Windows 与 Android 分别验证两个方向。

## 完整示例

~~~text
preview = inspect_source(private_address, pairing_code)
show_replacement_warning(preview)
require_explicit_confirmation()
staged = download_with_limit_and_sha256(preview)
inspect_backup(staged)
protection = create_backup(current_device)
try:
    restore_backup(staged)
    health_check()
catch:
    restore_backup(protection)
finally:
    clean_staging()
~~~

如果只是手动复制 ZIP、只在一台设备运行，或只通过单元测试，都不能算互联完成。

## 逐段解释

加密快照解决传输或存储泄漏的保密性；SHA-256 检查内容一致性，但没有签名时不能单独证明发送者身份。真正加密应使用成熟 AEAD、随机 nonce 和经 KDF 派生的密钥，不能自创算法。

整库替换能复用可靠备份恢复，缺点是覆盖接收端独有数据。逐条合并需要稳定设备 id、变更日志、删除墓碑和冲突规则，是另一阶段工程。

## 运行并观察

设计阶段先运行备份、恢复和路径安全测试。实现后运行错误配对、过期、断点、哈希不匹配、回滚和清理测试。最终在同一 Wi-Fi 真机验证 Windows→Android 与 Android→Windows，记录版本、大小、哈希和保护备份位置。

## 常见错误与修复

- 把两个安装包当作互联完成：必须做双向真机传输。
- 监听所有网卡后长期不关：仅主动开启并设置超时。
- 下载完直接解压：先检查大小、哈希、manifest 和路径穿越。
- 把 API Key 放进快照：敏感凭据必须排除。
- 显示“同步”却实际覆盖：明确写出方向和替换后果。
- 错误对象直接拼文字：结构化提取 code 和 message。

## 必做练习

画出发送与接收时序；列出绝不进入快照的信息；设计错误配对、断网和损坏包测试；写出接收前必须展示的五项摘要；说明首版为何不自动合并。

## 选做挑战

设计加密快照格式版本：正文使用标准 AEAD，密钥从口令经成熟 KDF 派生；列出密码错误、头部篡改和截断文件测试。实现前必须审查库与参数。

## 答案与思路

时序必须包含预览、确认、受限下载、校验、保护备份和回滚。敏感项含 API Key、认证令牌和系统凭据。缺少跨设备变更历史与冲突语义时，贸然合并更容易静默丢数据。
