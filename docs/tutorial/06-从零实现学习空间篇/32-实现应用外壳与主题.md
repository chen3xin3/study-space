# 第 32 章：实现应用外壳与主题——让每个页面住进同一个家

> 应用外壳不是装饰。它决定导航是否稳定、页面是否能独立滚动、用户能否知道自己在哪里，以及桌面和 Android 平板上是否都容易操作。

## 本章目标

你将亲手实现：

1. “学习空间”品牌区；
2. 首页、专注学习、学习资料、学习照片四个路由；
3. 首页第一、专注学习第二的导航顺序；
4. 固定在视口内的侧栏；
5. 侧栏和主内容互不干扰的独立滚动；
6. 统一的颜色、圆角、间距和文字层级；
7. 平板窄屏下自动收紧的导航；
8. 能保护布局要求的自动测试。

## 开始前需要会什么

请完成第 31 章，并确认教学应用的 npm run test 与 npm run build 能通过。你只需理解组件、数组的 map 和最基本 CSS。

## 新术语表

| 术语 | 白话解释 |
|---|---|
| App shell | 每个页面共用的外层结构 |
| Router | 根据 URL 决定显示哪个页面 |
| Route | 一条“路径 → 页面”的规则 |
| NavLink | 能知道自己是否指向当前页面的链接 |
| Design token | 集中保存颜色、尺寸等设计值的变量 |
| Viewport | 当前应用窗口可见区域 |
| 100dvh | 移动设备也较准确的一整个动态视口高度 |
| Independent scroll | 两个区域各滚各的 |
| Breakpoint | 到达某个宽度时切换布局的界线 |
| Accessible name | 读屏软件和测试识别控件使用的名称 |

## 先建立直觉

外壳就像学校教学楼：侧栏是楼层导览，主内容是教室。学生在教室里翻很长的资料时，导览牌不能一起被卷走；导览内容过长时，它可以自己滚动，但不能挤压教室。

主题也不是“全页刷成一种颜色”。舒服的界面通常有：

- 大面积安静的浅底色；
- 少量稳定的主色；
- 只在关键动作使用更鲜明的强调色；
- 重复使用同一套间距和圆角；
- 标题、正文、辅助文字有清楚但不过多的层级。

## 跟我一步一步做

### 第一步：先把布局要求写成测试

打开 [App.test.tsx](../labs/study-space-app/src/app/App.test.tsx)。第一条测试读取导航中的链接并确认顺序：

~~~tsx
expect(links.map((link) => link.lastElementChild?.textContent)).toEqual([
  "首页",
  "专注学习",
  "学习资料",
  "学习照片",
]);
~~~

第二条测试确认侧栏、主内容和 /focus 路由都存在。先写测试再实现，能阻止以后调整导航时无意把专注学习移回后面。

### 第二步：安装并引入路由

教学项目使用 react-router：

~~~tsx
import {
  BrowserRouter,
  MemoryRouter,
  NavLink,
  Route,
  Routes,
} from "react-router";
~~~

正常运行用 BrowserRouter；测试传入 initialEntries 时改用 MemoryRouter，这样不必真的操作浏览器地址栏。

### 第三步：把导航当数据写

~~~tsx
const navigation = [
  { to: "/", label: "首页", icon: "⌂", end: true },
  { to: "/focus", label: "专注学习", icon: "◷" },
  { to: "/materials", label: "学习资料", icon: "▤" },
  { to: "/photos", label: "学习照片", icon: "▧" },
];
~~~

统一数组比手写四段重复 JSX 更容易排序和测试。end: true 防止访问 /focus 时首页也因为 / 前缀而高亮。

### 第四步：建立语义清楚的结构

打开 [App.tsx](../labs/study-space-app/src/app/App.tsx)，核心结构是：

~~~tsx
<div className="app-shell">
  <aside className="app-sidebar">
    <nav aria-label="主导航">...</nav>
  </aside>
  <main className="app-content">
    <Routes>...</Routes>
  </main>
</div>
~~~

aside 表示辅助区域，nav 表示导航，main 表示当前页面的主要内容。正确 HTML 语义会同时帮助读屏软件、自动测试和后来维护代码的人。

### 第五步：使用 NavLink 自动高亮

~~~tsx
<NavLink
  to={item.to}
  end={item.end}
  className={({ isActive }) =>
    "nav-link" + (isActive ? " is-active" : "")
  }
>
~~~

不要自己维护一个“当前菜单索引”状态。URL 已经是当前页面的事实来源，NavLink 会据此提供 isActive。

### 第六步：声明路由

~~~tsx
<Routes>
  <Route path="/" element={<DashboardPage />} />
  <Route path="/focus" element={<FocusPage />} />
  <Route path="/materials" element={<MaterialsPage />} />
  <Route path="/photos" element={<PhotosPage />} />
</Routes>
~~~

本章先用 PlaceholderPage 占位，后续章节逐页替换。先搭路线、再装修房间，能避免一次修改过多。

### 第七步：建立主题变量

打开 [tokens.css](../labs/study-space-app/src/styles/tokens.css)：

~~~css
:root {
  --ink: #172622;
  --muted: #6e807a;
  --surface: #ffffff;
  --line: #dce7e2;
  --green: #327d67;
  --mint: #dff3ea;
  --coral: #ff7b69;
  --violet: #7664e8;
  --yellow: #f4c84c;
}
~~~

今后不要到处复制颜色代码。更换主题时改 token，页面继续引用含义明确的变量。

### 第八步：做真正独立的滚动

只写 fixed 不是最稳妥的方案。教学项目让最外层永远等于视口高度，并禁止整个 body 滚动：

~~~css
body { overflow: hidden; }

.app-shell {
  display: grid;
  grid-template-columns: var(--sidebar-width) minmax(0, 1fr);
  height: 100dvh;
  overflow: hidden;
}

.app-sidebar { min-height: 0; overflow-y: auto; }
.app-content { min-width: 0; min-height: 0; overflow-y: auto; }
~~~

min-width: 0 很重要：Grid 子项默认可能被长内容撑开，从而出现横向滚动。min-height: 0 则允许子项在限定高度内真正滚动。

### 第九步：适配 Android 平板宽度

~~~css
@media (max-width: 860px) {
  :root { --sidebar-width: 5.25rem; }
  .brand > span:last-child,
  .nav-link > span:last-child { display: none; }
  .nav-link { justify-content: center; }
}
~~~

窄屏保留图标和点击面积，隐藏长文字。真实项目还应给图标提供 title 或 aria-label，保证用户仍知道入口含义。

### 第十步：用触控标准检查

平板上没有鼠标的精确指针。主要导航至少约 44 像素高；教学项目使用 min-height: 3.25rem。还要检查：

1. 不依赖 hover 才显示关键操作；
2. 当前项不仅靠颜色区分，还用背景与阴影；
3. 主内容不会钻到侧栏下面；
4. 横屏与较窄竖屏都没有横向滚动。

## 逐段解释

### 为什么 App 只负责组合

App 应回答“有哪些全局区域和路由”，而不是塞入待办、照片、计时器的所有业务。页面组件负责业务，外壳负责共同结构，职责才不会缠在一起。

### 为什么背景可以多彩但内容卡片要克制

渐变被放在主内容的大背景上，透明度很低；真正承载文字的卡片仍接近白色。这样有个性但不影响阅读。多彩不等于每张卡片使用高饱和色。

### 为什么不用很多字体

教学项目只使用系统无衬线字体。风格来自字号、粗细、间距和色彩，而不是混入许多字体。跨 Windows 与 Android 时也更稳定。

### 为什么测试不检查 CSS 像素

组件测试适合保护结构、顺序和行为。精确视觉需要真实浏览器截图或人工查看。如果测试把每个像素写死，稍微调整圆角就会产生大量无价值失败。

## 常见错误与修复

### 首页在所有页面都高亮

给首页 NavLink 添加 end，让它只在路径精确等于 / 时激活。

### 右侧出现横向滚动条

给 Grid 的内容列使用 minmax(0, 1fr)，并给 app-content 设置 min-width: 0。

### 侧栏仍随页面移动

确认滚动发生在 app-content，不是 body。最外层需要固定为 100dvh，body 需要 overflow: hidden。

### 平板上按钮太难点

不要只缩小字体；保留至少约 44 像素的触控高度与足够间距。可以隐藏文字，但不能把触控区一起缩成小点。

### 测试中 BrowserRouter 相互影响

测试使用 MemoryRouter 并为每个用例传 initialEntries，不依赖真实浏览器历史。

## 选做挑战

实现“收起导航”按钮：桌面宽屏时允许用户手动在 15rem 和 5.25rem 间切换；把选择保存在 localStorage；按钮必须有明确的 aria-label，重开页面后保持上次状态。

## 答案与思路

新增路由要同时改导航数组和 Routes，然后更新顺序测试。主题练习只改 green、mint 等变量，若组件中还有散落颜色就把它们抽成新 token。独立滚动的关键不是固定定位，而是“外壳限定高度 + body 不滚 + 两个子区域分别 overflow”。

收起功能可用布尔状态控制根元素类名，再让 CSS 切换侧栏宽度。读取本地存储时要给缺失和无效值默认行为。
