# 第 36 章：实现学习照片与文件

## 本章目标

实现图片类型与大小校验、日期和分类元数据、预览 URL、回收站、恢复及确认后的永久删除，并理解桌面与 Android 文件路径差异。

## 开始前需要会什么

理解 File、MIME、软删除和依赖注入。

## 新术语表

| 术语 | 含义 |
|---|---|
| MIME type | 文件内容类型标识 |
| Object URL | 浏览器为本地对象生成的临时预览地址 |
| Revoke | 释放临时预览地址占用的资源 |
| Managed copy | 复制进应用自己管理的目录 |
| content URI | Android 授予应用访问内容的地址 |

## 先建立直觉

照片卡片不是文件本身。卡片保存名称、日期、分类等元数据；真实字节需要进入受管目录。浏览器 object URL 只是临时观景窗，删除或卸载预览时必须关闭。

## 完整示例

~~~ts
const file = new File(["image bytes"], "paper.jpg", { type: "image/jpeg" });
const photo = createPhotoRecord(file, "2026-10-15", "英语试卷", objectUrls);
const trashed = trashPhoto([photo], photo.id);
const restored = restorePhoto(trashed, photo.id);
~~~

## 逐段解释

扩展名可以伪造，所以至少检查 MIME；后端还应检查文件头。object URL 指向内存或浏览器持有的对象，不释放会泄漏资源。数据库事务不能撤销磁盘复制，真实导入使用暂存文件、事务和失败补偿。

## 运行并观察

选择练习图片，切换日期和分类，移入回收站再恢复。尝试文本文件应被拒绝。永久删除时应出现确认。运行 npm run test、npm run build 与 Rust 附件测试。

## 常见错误与修复

- 只看 .jpg 扩展名：同时检查 MIME，后端再识别文件头。
- 永久保存 blob URL：它只在当前环境临时有效。
- 不 revoke：大量图片会持续占用资源。
- 直接引用下载目录：文件移动后失效，应复制到受管目录。
- 把 content:// 当 Windows 路径：Android 应通过内容读取 API 获取字节。

## 答案与思路

筛选只作用元数据；确认值必须传入领域函数而不只依赖弹窗；object URL 是临时浏览资源，受管路径是应用长期控制的磁盘位置；失败时删除暂存文件并回滚或标记数据库记录。
