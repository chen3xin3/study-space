# 第 34 章：实现学习资料系统

## 本章目标

建立能保存标题、学科、类型、掌握度、收藏和版本的资料模型，实现搜索、筛选、回收站、恢复与版本冲突保护。

## 开始前需要会什么

理解第 33 章的纯函数、不可变更新与软删除。

## 新术语表

| 术语 | 含义 |
|---|---|
| Entity | 有稳定 id 的业务对象 |
| Filter | 只显示符合条件的数据 |
| Optimistic concurrency | 用版本号拒绝旧页面覆盖新数据 |
| Trash | 软删除记录的查看区域 |
| Mastery | 对资料掌握程度的业务字段 |

## 先建立直觉

资料库不是背单词页面。它负责收藏和整理单词照片、作文、试卷、错题与笔记，让你以后找得到；真正的练习和复习可以在其他页面发生。

## 图解

## 跟我一步一步做

1. 阅读 [materials.test.ts](../labs/study-space-app/src/domain/materials.test.ts)，先确定校验、检索、删除恢复和冲突行为。
2. 在 [materials.ts](../labs/study-space-app/src/domain/materials.ts) 定义 LearningMaterial 与 MaterialDraft。
3. createMaterial 对标题、学科和掌握度做边界校验，同时产生 version=1。
4. filterMaterials 一次组合关键词、学科、收藏和 active/trash 模式。
5. updateMaterial 接收 expectedVersion；不一致就抛“资料已在其他位置更新”，一致才 version+1。
6. 在 [MaterialsPage.tsx](../labs/study-space-app/src/pages/MaterialsPage.tsx) 做清楚的录入区与资料列表，不混入复习游戏。
7. 回收站提供恢复；永久删除在真实项目中必须额外确认并处理附件。

## 完整示例

~~~ts
const item = createMaterial({
  title: "英语一作文模板",
  subject: "英语",
  kind: "作文",
  mastery: 2,
  favorite: true,
});
const found = filterMaterials([item], {
  query: "作文",
  subject: "全部",
  favoriteOnly: true,
  mode: "active",
});
~~~

## 逐段解释

UI 类型限制能减少误操作，但后端仍必须校验，因为调用者不一定是当前表单。版本号解决的是“两个窗口先后保存”问题：后保存的旧副本不能静默覆盖新内容。教学版只展示核心思想，真实系统还会处理附件、集合、分页、同步和事务。

## 运行并观察

进入学习资料，分别保存英语试卷和数学错题；搜索“英语”；切到回收站并恢复。运行 npm run test 与 npm run build，确认资料测试和类型检查通过。

## 常见错误与修复

- 把资料库做成背词工具：先守住“存、找、整理”的职责。
- 搜索只查标题：可组合学科和类型，但不要未经设计搜索隐私附件正文。
- 更新时不带版本：旧页面可能覆盖新修改。
- 删除直接移除附件：数据库与文件可能只成功一半，应使用事务与补偿。
- 收藏和筛选分别维护数组：保存一份源数据，展示时派生。

## 选做挑战

加入 collectionId 实现资料集合，并设计“删除集合时资料如何处理”的三种方案，明确你选择哪一种及理由。

## 答案与思路

掌握度可成为 filter 条件；同名通常可以允许但用学科和日期区分；两个副本都携带 version=1，第一个保存升到 2，第二个再保存必须失败；恢复仍应增加版本以表达数据发生变化。
