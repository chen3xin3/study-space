# 第 33 章：实现首页和今日待办

## 本章目标

实现可新增、完成和软删除的今日待办，保留学习日历与最近七天趋势，并理解从事件、状态到界面重绘的完整路径。

## 开始前需要会什么

完成第 32 章，能运行教学应用测试；理解 state、表单提交、数组 map/filter 和不可变更新。

## 新术语表

| 术语 | 含义 |
|---|---|
| Domain function | 不依赖界面的业务函数 |
| Immutable update | 返回新对象，不修改旧对象 |
| Soft delete | 记录删除时间而非直接消失 |
| Derived state | 从已有状态计算出的值 |
| Zero fill | 没记录的日期仍补为 0 |

## 先建立直觉

首页不是入口广告墙，而是每天真正会使用的驾驶舱。最重要的是“下一件要做什么”，日历回答“哪些天学过”，趋势回答“最近是否稳定”。快速开始之类重复入口反而会分散注意力。

## 逐段解释

任务数组是事实数据；完成数量属于派生数据，不需要再存一个 state。否则修改任务后容易忘记同步数量。趋势同理：存每日分钟记录，展示时才补齐七天。教学版暂存在内存中；真实项目把相同意图交给服务层和 SQLite。

## 运行并观察

运行 npm run dev，新增两项任务、勾选一项、移除一项。确认空标题无法提交，页面刷新后数据会清空——这是教学版尚未连接数据库的预期现象。再运行 npm run test 和 npm run build。

## 常见错误与修复

- 直接修改 task.completed：React 可能看不到引用变化，改用 map 返回新对象。
- 用数组下标作 id：排序后会操作错误项目，使用稳定 id。
- 趋势只返回有数据的日子：图表横轴会跳动，先生成完整日期范围。
- 永久 splice 删除：失去恢复与同步能力，先做软删除。
- 表单按钮触发页面刷新：在 submit 中调用 preventDefault。

## 必做练习

增加“只看未完成”筛选；给空标题写测试；把七天摘要改为接受任意结束日期；说明为什么删除后仍保留记录。

## 选做挑战

加入任务学科、预计轮数和拖拽排序。排序字段必须保存为显式 order，不能把当前数组下标当长期顺序。

## 答案与思路

筛选属于派生结果，可在渲染前 filter；输入错误应在纯函数和表单双层保护；自定义日期仍按本地自然日逐日倒推；软删除为恢复、同步和审计留下余地。
