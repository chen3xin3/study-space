# 第 47 章：怎样阅读陌生代码

## 本章目标

不从第一行开始硬读，而是从用户行为、入口、类型、测试和调用边界建立地图，逐步理解陌生模块。

## 开始前需要会什么

会使用文件搜索和文本搜索，理解页面、服务、command、仓储与数据库分层。

## 新术语表

| 术语 | 含义 |
|---|---|
| Entry point | 一条功能开始执行的位置 |
| Call graph | 函数与模块之间的调用关系 |
| Data flow | 数据从输入到存储再到输出的路线 |
| Invariant | 无论怎样操作都必须成立的规则 |
| Public contract | 模块向外公开的类型和函数 |
| Hot path | 高频或关键执行路径 |

## 先建立直觉

阅读一座城市不需要进入每栋楼。先看地图、主干道和目的地，再走一条真实路线。代码也一样：先回答“点击这个按钮后去了哪里”。

## 图解

~~~mermaid
flowchart LR
  A[用户行为/路由] --> B[页面组件]
  B --> C[公开类型]
  B --> D[服务接口]
  D --> E[Tauri adapter]
  E --> F[Rust command]
  F --> G[仓储/文件]
  G --> H[SQLite]
  I[测试] -.说明规则.-> B
  I -.说明规则.-> D
  I -.说明规则.-> G
~~~

## 跟我一步一步做

1. 先运行应用，看清用户流程，不在没有问题时阅读所有文件。
2. 从路由或按钮文字搜索页面入口。
3. 先读文件顶部 import、props/type 和导出，知道依赖与公开接口。
4. 查看同名测试，测试名称通常直接说明必须保持的行为。
5. 找页面调用的服务方法，不急着进入所有 UI 子组件。
6. 沿 Tauri adapter 的 command 名搜索 Rust 注册位置。
7. command 应很薄，继续进入数据模块或仓储。
8. 找 SQL、文件写入和事务边界，记录真正改变数据的位置。
9. 画一张小调用图，只写函数名、输入和输出。
10. 回头阅读错误与空状态，补全失败路线。
11. 只在需要修改的区域深入细节。
12. 用一个小测试验证你的理解，不靠记忆猜测。

## 完整示例

要理解“结束并复盘”：

1. 搜索按钮文本找到 FocusPage；
2. 看 FocusReviewDialog 的提交 props；
3. 查 focus service 的 finish 方法；
4. 搜索 invoke command 名；
5. 阅读 Rust command 输入模型；
6. 进入 focus 数据层事务；
7. 查看对应测试，确认学习时长、中断、任务完成与版本冲突规则；
8. 画出调用链并用固定时间测试验证休息未计时。

## 逐段解释

类型是压缩后的设计文档：字段名说明数据，联合类型说明允许状态，接口说明可用能力。测试则揭示隐含规则。CSS 和视觉子组件通常最后读，除非问题本身是布局。

遇到大文件先找导出、事件处理、Effect 和服务调用，不要逐字符阅读。理解只需覆盖当前任务需要的路径。

## 运行并观察

选择英语照片导入，从路由开始沿调用链写出十行笔记。每走一层记录文件、函数、输入、输出、错误。最后用现有测试验证你的图是否遗漏草稿或附件步骤。

## 常见错误与修复

- 从仓库第一个文件顺序读：围绕一个行为纵向切片。
- 遇到陌生语法就停：先判断是否影响当前调用链。
- 只读页面不读服务：会误判数据来源。
- 只读实现不读测试：遗漏不变量。
- 猜数据库字段含义：查看模型、迁移和查询。
- 阅读时顺手大规模重构：先完成理解，再单独规划。

## 必做练习

分别画“创建今日任务”“导入作文照片”“结束专注”调用链；给每层写一句职责；找出一个必须成立的不变量；用测试证明它。

## 选做挑战

为一个陌生模块制作一页代码地图：入口、类型、服务、command、存储、测试、风险和未理解问题。限制一页，训练抓主线。

## 答案与思路

调用链不需要列每个展示组件，但必须包含改变数据的边界。职责示例：页面收集意图、服务统一合同、adapter 翻译协议、command 校验并委托、仓储保证事务。测试选择最关键不变量。
