# 第 49 章：毕业项目——独立完成“试卷复盘工作台”

> 最终目标不是一次写出很多代码，而是独立走完需求、调查、设计、测试、实现、调试、安全检查、双端适配和发布验收。

## 本章目标

在不依赖逐行答案的情况下，为“学习空间”独立实现试卷复盘工作台：保存试卷原图、整理题目与错因、关联学科资料、安排复习，并交付经过验证的 Windows 与 Android 版本。

## 开始前需要会什么

完成前 48 章；能使用 Git 隔离工作、编写计划、读陌生代码、运行完整验证并保护真实数据。

## 先建立直觉

毕业项目不是“再做一个页面”。它贯穿全栈：原图进入附件系统，试卷和题目进入数据库，错因成为结构化资料，复习任务回到首页，专注记录进入统计，AI 只能提供待确认建议。

## 跟我一步一步做

### 阶段一：定义第一版

必须包含：

1. 创建试卷记录：标题、学科、考试日期、总分和备注；
2. 导入一张或多张原始照片，保存受管附件；
3. 创建题目记录：题号、题型、得分、错因、知识点和复习状态；
4. 按学科、日期、知识点和“只看错题”筛选；
5. 从错题创建今日复习任务，并可进入专注学习；
6. 软删除、回收站和恢复；
7. 重开应用后数据仍在；
8. Windows 与 Android 平板均可操作。

非目标建议：第一版不自动切题、不自动判分、不做多人协作、不做云同步。

### 阶段二：调查现有能力

寻找可以复用的照片导入、学习资料、今日任务、专注计划、软删除、版本冲突、附件和备份模块。制作文件地图，明确哪些是新增代码，哪些只是组合已有服务。

### 阶段三：写设计

至少包含：

- 用户流程和空/错/加载/保存中状态；
- Paper、Question、AttachmentLink 的字段；
- 数据库迁移和索引；
- 页面、服务、command 与仓储接口；
- 文件导入事务补偿；
- Android content URI 处理；
- AI 可选建议的确认边界；
- 旧版本备份兼容与回滚。

### 阶段四：写计划

按依赖拆分：

1. 类型与纯校验测试；
2. 追加迁移与仓储测试；
3. 附件关联和失败补偿测试；
4. 服务 contract 与浏览器 fake；
5. 列表、编辑器、详情与回收站组件测试；
6. 任务和专注联动；
7. 平板布局与无障碍；
8. 完整测试、构建和真机验收。

每项独立提交，不混入无关视觉重构。

### 阶段五：测试驱动实现

最少覆盖：

- 空标题、非法分数和重复题号；
- 创建、更新、软删除、恢复和版本冲突；
- 照片大小、MIME、哈希和失败清理；
- 筛选和零数据；
- 创建复习任务不重复；
- 休息不计入复习专注时间；
- 页面重开恢复；
- Android 窄屏无横向滚动；
- 备份恢复后试卷与附件一致。

### 阶段六：安全与隐私

不使用真实敏感试卷做自动测试。AI 默认不发送整张试卷；用户明确选择后才发送，并显示范围。诊断报告移除正文、图片与密钥。永久删除需要确认并协调文件。

### 阶段七：发布验收

运行完整前端与 Rust 测试、两端构建和差异检查。在真实 Windows 与 Android 上分别新建、导入、编辑、重启、筛选、创建复习任务、专注、备份和恢复。

## 完整示例

一个合格的验收故事：

给定用户在 Android 导入一份 2026-10-15 数学试卷的三张照片，并录入第 12 题得分 0、错因“忽略定义域”；当用户保存、关闭应用再打开并筛选“数学 + 只看错题”时，仍能看到第 12 题和三张原图；当点击“加入明日复习”时，只创建一项关联任务；完成 25 分钟学习和 5 分钟休息后，统计只增加 25 分钟。

## 逐段解释

这个项目验证了所有核心能力：需求范围、关系模型、迁移、文件生命周期、跨模块服务、时间规则、测试、安全和发布。AI 并非必需项；若加入，只能建议知识点、错因分类或摘要，并保留人工确认。

不要追求一次做到完美。先交付可靠的手工流程，再用真实使用体验决定是否需要 OCR、自动裁题或智能复习。

## 运行并观察

每个里程碑完成后保存演示数据与测试结果。最终至少执行：

~~~powershell
npm run test:run
npm run build
cargo test --manifest-path src-tauri/Cargo.toml
cargo check --manifest-path src-tauri/Cargo.toml
git diff --check
git status --short
~~~

再完成 Windows 与 Android 真机验收。自动测试不能代替文件选择、触控、旋转、升级和安装检查。

## 常见错误与修复

- 一开始做 OCR 自动切题：先完成可靠手工闭环。
- 修改旧迁移：新增迁移并测试旧库升级。
- 题目直接存图片绝对路径：使用附件 id 与受管副本。
- 一次提交几千行：按可验证里程碑拆分。
- 只测试成功路径：加入空间不足、取消、冲突和损坏文件。
- 为赶进度跳过备份：涉及真实数据前先验证恢复。
- UI 很漂亮但无法重开恢复：持久化是验收条件。

## 选做挑战

在核心项目完成后任选一项：AI 建议知识点、局域网快照传输、加密导出、错题复习间隔算法或试卷区域手动裁切。每项都必须重新写范围、风险和测试，不能直接塞进核心流程。

## 答案与思路

毕业项目没有唯一源码答案。评分重点是：

| 维度 | 达标表现 |
|---|---|
| 需求 | 目标、非目标和验收清晰 |
| 架构 | 页面、服务、command、仓储职责分明 |
| 数据 | 迁移追加、版本冲突、附件一致 |
| 测试 | 关键规则先失败后通过 |
| 安全 | 最小权限、受管路径、备份可恢复 |
| 双端 | Windows 与 Android 真机完成核心流程 |
| 过程 | 提交小、记录清楚、无无关修改 |
| 独立性 | 能解释每个选择并自行查证 |

遇到困难时回到最小闭环：一份试卷、一张照片、一条错题、一次保存和一次重开。先让它可靠，再扩大。
