# 第 43 章：调试与故障排查

## 本章目标

建立可重复的排错流程：重现、收集证据、缩小范围、提出单一假设、验证修复和补回归测试；能跨 React、Tauri、Rust、SQLite 与 Android 定位问题。

## 开始前需要会什么

能阅读终端错误、浏览器控制台、测试失败和基本调用链。

## 新术语表

| 术语 | 含义 |
|---|---|
| Reproduction | 稳定触发问题的最短步骤 |
| Evidence | 日志、状态、输入输出和堆栈等事实 |
| Hypothesis | 对原因的可验证猜测 |
| Bisect | 逐步缩小问题出现范围 |
| Boundary | 页面、服务、command、仓储等交界 |
| Diagnostic report | 脱敏后的环境与错误摘要 |

## 先建立直觉

调试像医生诊断：先确认症状和条件，再看证据。一次同时改五个地方，即使问题消失也不知道真正原因，还可能制造新问题。

## 图解

~~~mermaid
flowchart TD
  A[准确重现] --> B[记录环境/输入/错误]
  B --> C[找最后正常边界]
  C --> D[提出一个假设]
  D --> E[最小实验]
  E -->|不支持| C
  E -->|支持| F[回归测试]
  F --> G[最小修复]
  G --> H[局部+完整验证]
~~~

## 跟我一步一步做

1. 写下环境、版本、页面、输入、期望、实际结果和发生频率。
2. 从用户动作沿页面 → 服务 → invoke → command → 数据层追踪。
3. 在边界检查结构化值，不打印密钥、完整作文或私人照片路径。
4. 判断属于渲染、状态、异步、序列化、数据库、文件、权限还是平台。
5. 把问题缩成最小测试；能在纯函数重现就不要反复启动桌面端。
6. 一次只验证一个假设，例如“页面切换后 interval 未清理”。
7. 用失败测试固定症状，再做最小修改。
8. 检查失败路径和相邻功能，不只重走成功路径。
9. 移除临时日志，保留有价值且脱敏的诊断。
10. 记录根因、修复和预防措施。

## 完整示例

界面出现 object Object：重现结束复盘失败 → 发现 catch 收到结构化对象 → 服务直接 String(error) → 写测试传入 code/message → 期望展示 message → 实现统一解析器 → 运行服务、页面和完整测试。

## 逐段解释

“最后正常边界”很有效：按钮触发了吗？服务收到参数了吗？invoke 名对吗？Rust 反序列化成功吗？SQL 返回行吗？文件存在吗？每回答一项，范围就缩小。

单独通过而全量超时常提示资源竞争、测试隔离或等待条件问题，不能只扩大超时掩盖。

## 运行并观察

打开 [诊断服务](../../../src/services/diagnostics/diagnostics.service.ts) 与 [Rust 诊断模块](../../../src-tauri/src/diagnostics.rs)，确认报告包含版本和健康信息但不泄露秘密。挑一个测试用名称过滤单独运行，再回到完整测试。

## 常见错误与修复

- 没重现就改：先得到稳定步骤。
- 只看错误最后一行：向上找第一个项目堆栈。
- 用清缓存解决一切：只有证据指向缓存才清。
- 同时升级依赖和修 bug：分开变量。
- 超时从 1 秒改 10 秒：先找等待条件与竞争。
- 日志打印完整请求：先脱敏。

## 必做练习

为 object Object 错误写排查记录；画出照片导入边界；分析一个单独通过但全量失败的测试；分别写三条证据和猜测。

## 选做挑战

制作脱敏诊断模板，包含版本、平台、数据库健康和最近错误码，但移除 API Key、绝对私人路径、正文和图片内容。

## 答案与思路

证据是可观察事实，猜测必须可被实验推翻。异步问题优先检查未清理定时器、共享 fake、未等待状态和并发资源。诊断报告应默认最小化并允许用户预览。
