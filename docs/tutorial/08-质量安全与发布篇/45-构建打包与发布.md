# 第 45 章：构建、打包与发布

## 本章目标

理解开发版、生产前端、Windows 安装包与 Android APK 的区别，掌握版本、名称、签名、产物检查和发布验收。

## 开始前需要会什么

能运行 npm、Cargo 和 Tauri 命令，理解配置、环境变量与 Git 提交。

## 新术语表

| 术语 | 含义 |
|---|---|
| Artifact | 安装包、APK 或编译库 |
| Bundle | 把前端、Rust 与资源打成应用 |
| Signing | 用密钥证明发布者 |
| ABI | Android CPU 架构，例如 arm64 |
| Release build | 面向用户的优化构建 |
| Version code | Android 判断升级顺序的整数 |
| Smoke test | 安装后快速验证核心路径 |

## 先建立直觉

npm run build 只生成网页资源，不是 Windows 安装包；Cargo check 只验证 Rust 编译；Tauri build 才把两边和图标、名称、权限组合成平台应用。每一层成功证明的事情不同。

## 图解

~~~mermaid
flowchart LR
  A[React] --> B[npm build]
  B --> C[dist]
  D[Rust] --> E[cargo test/check]
  C --> F[tauri build]
  E --> F
  F --> G[Windows installer]
  F --> H[Android APK/AAB]
  G --> I[干净设备验收]
  H --> I
~~~

## 跟我一步一步做

1. 确认 Git 状态和版本目标；不要批量改名历史安装包。
2. 统一 package.json、Tauri productName、窗口标题、Android productName 与应用品牌。
3. 运行完整前端测试和 npm run build。
4. 运行 cargo test、cargo check 和必要静态检查。
5. 用 npm run tauri build 构建 Windows 安装包，记录精确路径。
6. 使用 Tauri Android build 构建目标 ABI；平板通常至少需要 aarch64。
7. 发布包使用妥善保管的签名密钥；测试密钥不能用于正式发布。
8. 检查名称、版本、图标、窗口标题、托盘提示和卸载项。
9. 在无开发工具的 Windows 环境与真实 Android 平板安装。
10. 做升级测试：旧版本有数据 → 安装新版本 → 迁移成功 → 数据仍在。
11. 明确卸载和重装时用户数据是否保留。
12. 发布记录写明已知问题、兼容性、文件哈希和回滚方式。

## 完整示例

~~~powershell
npm run test:run
npm run build
cargo test --manifest-path src-tauri/Cargo.toml
cargo check --manifest-path src-tauri/Cargo.toml
npm run tauri build
npm run tauri android build -- --apk --target aarch64 --split-per-abi
~~~

命令会受本机 Android SDK、NDK、签名和 Windows 组件影响。失败时先读第一个项目相关错误，不要盲目重装全部工具。

## 逐段解释

版本号是兼容合同。数据库迁移只能追加，安装包版本、应用显示版本和备份格式要可追踪。签名密钥丢失可能使用户无法原地升级；泄露则允许他人冒充发布。

模拟器不能完全代替平板：相册选择器、content URI、触控、旋转、返回键和后台策略需要真机。

## 运行并观察

先查看前端 dist，再运行 Tauri 开发版，最后构建平台包。安装后测试首页、导入、专注恢复、备份恢复、AI 设置和诊断。记录平台、版本、时间、大小与 SHA-256。

## 常见错误与修复

- 把 dist 当安装包：使用 Tauri bundle。
- 只改界面名称：同步配置、窗口、Android 标签和托盘。
- 提交 target、dist、gen 或 APK：生成物不进源码历史。
- 用测试签名正式发布：建立独立发布密钥。
- 只测全新安装：必须测试带旧数据升级。
- 构建成功就称双端可用：还需安装与真机流程验收。

## 选做挑战

设计本地发布脚本：运行测试、构建、收集产物、计算 SHA-256 和生成发布清单；任一步失败立即停止，且不覆盖旧发布文件。

## 答案与思路

前端 build 证明网页可打包，Cargo 证明 Rust 编译与测试，Tauri build 生成平台包，真机验收才证明安装后流程可用。发布脚本使用新目录和版本化名称。
