# 第 44 章：安全与数据保护

## 本章目标

建立威胁建模、最小权限、输入校验、密钥保护、路径安全、备份恢复和隐私日志的系统观念。

## 开始前需要会什么

理解前后端边界、附件、SQLite、备份、AI Provider 和设备互联。

## 新术语表

| 术语 | 含义 |
|---|---|
| Threat model | 资产、攻击面、对手和防护清单 |
| Least privilege | 只授予完成任务所需权限 |
| Path traversal | 利用路径跳出受管目录 |
| Secret | API Key、令牌等不能公开的信息 |
| Integrity | 数据未被意外或恶意修改 |
| Confidentiality | 未授权者无法读取数据 |
| Availability | 数据在需要时仍可使用 |

## 先建立直觉

安全不是最后加一个密码。每条数据路径都要问：输入从哪来、谁能调用、写到哪里、失败会不会丢数据、日志会不会泄露、用户能否恢复。

## 图解

~~~mermaid
flowchart TD
  A[资产: 数据库/照片/密钥] --> B[入口: 表单/文件/网络/备份]
  B --> C[校验与权限]
  C --> D[受管存储]
  D --> E[备份与恢复]
  D --> F[日志与诊断脱敏]
  G[攻击/误操作/断电] --> C
  G --> E
~~~

## 跟我一步一步做

1. 列出资产：学习记录、作文、照片、附件、AI 密钥、备份和设备身份。
2. 列出入口：表单、文件选择、Tauri command、网络响应、备份 ZIP 与局域网请求。
3. 前端做体验校验，Rust 做可信校验；前端不是安全边界。
4. SQL 使用参数绑定，不拼接用户输入。
5. 文件名由应用生成，拒绝绝对路径、..、重复条目和清单外文件。
6. 限制 MIME、大小、数量和解压总量，防止磁盘耗尽。
7. API Key 进入安全凭据层，前端只知道 hasApiKey。
8. CSP 只开放必要来源；新增网络域名必须审查。
9. 删除默认软删除；永久删除明确确认并协调数据库与附件。
10. 恢复先验证候选，再建保护备份，替换后做健康检查。
11. 日志记录错误码和必要上下文，不记录密钥、认证头、正文或图片。
12. Android 权限最小化，不为方便添加广泛存储、位置或后台权限。

## 完整示例

安全导入：读取明确选择的文件 → 检查大小和 MIME → 生成受管名 → 写暂存目录 → 算 SHA-256 → 短事务保存元数据 → 原子移动 → 失败清理。外部路径不直接成为长期路径。

## 逐段解释

完整性、保密性和可用性常有取舍。加密保护保密性，但丢口令损害可用性；哈希检查完整性但不等于加密；备份增加可用性，也增加敏感副本数量。

AI 资料中的文字是不可信数据。系统提示与用户资料必须分隔，输出仍需结构校验和人工确认。

## 运行并观察

运行附件、备份、AI 凭据、服务错误和 command 测试。检查差异中是否出现密钥、真实数据库、照片、备份包或日志。导出诊断报告并预览敏感字段。

## 常见错误与修复

- 前端 disabled 就认为安全：后端重新校验。
- 自创加密算法：使用成熟库和标准 AEAD。
- 日志打印整个请求：映射为脱敏字段。
- 解压前只看 ZIP 大小：还要限制条目和解压总量。
- 恢复先覆盖再验证：必须反过来。
- 开发密钥提交 Git：撤销密钥、清理历史并改用安全存储。

## 必做练习

为照片导入画威胁模型；找出五个必须后端校验的字段；写备份恢复顺序；列出诊断报告禁止字段；检查 Android 权限是否匹配功能。

## 选做挑战

建立安全回归清单：秘密扫描、危险路径、备份大小边界、CSP、日志脱敏和依赖漏洞审查。自动工具结果仍需人工判断。

## 答案与思路

威胁至少含路径逃逸、超大文件、伪造 MIME、重复提交和断电。后端校验 id、version、枚举、大小和路径。恢复顺序是候选验证 → 保护备份 → 替换 → 再验证 → 失败回滚。
