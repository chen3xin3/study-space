# 第 14 章：泛型、类型缩小与实用类型

## 本章目标

2. 看懂 Array<StudyTask> 和 Promise<StudyTask[]>；
3. 使用 Pick、Omit 和 Partial 生成用途明确的新类型；

7. 定义页面可调用、实现可替换的 TaskService；

## 新术语表

| 术语 | 普通话解释 |
| --- | --- |
| 泛型 | 用类型参数表达“输入类型与输出类型的关系” |
| 类型参数 | 暂时代表某种类型的名称，例如 T |
| 实用类型 | TypeScript 提供的类型变换工具 |
| Pick | 从对象类型挑选一部分字段 |
| Omit | 从对象类型排除一部分字段 |
| Partial | 把对象字段暂时变成可选 |
| 类型缩小 | 根据判断，把宽泛类型缩小成具体类型 |
| unknown | 未知值，判断前不能随意操作 |
| 判别联合 | 使用共同标记字段区分多个对象状态 |
| 接口契约 | 调用方与实现方都遵守的方法和类型约定 |
| 依赖注入 | 从外部提供实现，而不是组件自己创建 |
| 浅复制 | 复制对象第一层，嵌套引用可能仍共享 |

## 先建立直觉

假设快递箱上写着“里面装的东西类型为 T”。箱子不关心 T 最终是书、衣服还是任务，但取出时仍能知道它与装入时是同一种类型。泛型表达的就是这种关系。

Promise<StudyTask[]> 表示：现在得到一个 Promise，将来成功时得到 StudyTask 数组。Array<StudyTask> 表示数组里的每一项都是 StudyTask。

实用类型则像从完整表格生成不同用途的表单。保存后的 StudyTask 有 ID 和完成状态，但“创建任务”输入只需要标题与科目，所以使用 Pick 选出这两个字段。

## 跟我一步一步做

### 第一步：看懂数组泛型

下面两种写法等价：

    const first: StudyTask[] = [];
    const second: Array<StudyTask> = [];

Array 后面的尖括号告诉检查器数组元素类型。它不是函数调用，运行时不会创建一个名为 StudyTask 的对象。

### 第二步：看懂 Promise 泛型

    function list(): Promise<StudyTask[]>

它表示 list 立即返回 Promise，await 成功后得到 StudyTask 数组。错误写法是把 Promise 当数组直接读取 length。

### 第三步：从完整类型挑选创建字段

参考 [task-service.ts](../labs/react-basics/src/services/task-service.ts)：

    export type CreateTaskInput =
      Pick<StudyTask, "title" | "subject">;

这会得到等价结构：

    {
      title: string;
      subject: StudySubject;
    }

ID 由服务创建，completed 使用默认值，所以调用页面不应负责这两个字段。

### 第四步：定义服务契约

    export interface TaskService {
      list(): Promise<StudyTask[]>;
      create(input: CreateTaskInput): Promise<StudyTask>;
      toggle(id: string): Promise<StudyTask>;
    }

接口只说明“能做什么”，没有说明数据存在哪里。页面以后可以使用内存实现、浏览器实现或 Tauri 实现。

### 第五步：从 unknown 取得错误文字

    function getErrorMessage(error: unknown): string {
      return error instanceof Error
        ? error.message
        : "发生了未知错误";
    }

catch 中的值可能不是 Error。instanceof 是运行时证据，让 TypeScript 在真分支把 unknown 缩小成 Error。

### 第六步：表达界面状态

    type LoadState =
      | { status: "idle" }
      | { status: "loading" }
      | { status: "success"; tasks: StudyTask[] }
      | { status: "error"; message: string };

status 是判别字段。当 status 为 success 时，检查器知道 tasks 存在；为 error 时，message 存在。

### 第七步：运行服务测试

    npm run test:run -- docs/tutorial/labs/react-basics/src/services/in-memory-task-service.test.ts

预期 3 项通过：返回克隆、创建任务、切换与未知 ID 错误。

## 逐段解释

### 类型参数为什么有用

没有泛型时，容器可能只能返回 unknown，调用方每次都要判断。泛型让“装入什么，取出什么”的关系保留下来。

### Pick 与 Omit

Pick 选择需要字段，Omit 排除不需要字段。选择少量字段时 Pick 更清楚；保留大部分、排除少量时 Omit 更自然。

### Partial 的边界

Partial<StudyTask> 把所有字段变成可选，适合补丁或测试覆盖值，不适合替代正式 StudyTask。否则页面会到处面对 undefined。

### unknown 与 any

unknown 要求先证明类型；any 允许直接调用任何属性。外部数据和 catch 错误优先 unknown。

### 类型缩小

typeof、instanceof、in 运算符和字面量比较都能提供证据。断言只是告诉检查器“相信我”，不等于真实验证。

### 克隆为什么必要

服务返回内部对象本身时，调用者可以绕过服务直接修改数据。内存服务通过展开语法复制第一层，保护简单扁平模型。

### 接口不包含实现

TaskService 没有数据库路径、延迟或 Tauri 命令名。这使调用方依赖稳定能力，而不是某个技术细节。

## 运行并观察

### 观察 Promise 返回值

不使用 await 调用 service.list，Console 会显示 Promise。加 await 后才得到数组。

### 观察克隆

测试先取得列表并修改第一项标题，再次 list。第二次标题未被污染，证明服务没有泄露内部对象。

### 观察类型缩小

删除 instanceof 判断后读取 error.message，严格检查会拒绝。恢复判断后通过。

### 观察错误路径

调用不存在的 ID，Promise rejected 为“任务不存在”。测试使用 rejects 验证，而不是让未处理拒绝污染输出。

## 常见错误与修复

### 把泛型当成高级数学

先读成“装着某种类型的容器”。只关注当前输入输出关系，不必一次掌握泛型约束和条件类型。

### 滥用 Partial

如果函数必须得到标题，就不要接收 Partial<CreateTaskInput>。可选过多会把校验责任扩散。

### 用 as Error 强制错误类型

catch 值可能是字符串或对象。使用 instanceof Error 提供证据。

### 接口方法返回任意对象

明确写 Promise<StudyTask>，让实现与调用方共享约定。

### 页面直接创建服务

这会让测试难以替换实现。后续在应用边界创建，再传给页面。

### 误以为浅复制能复制所有嵌套

展开语法只复制一层。当前模型是扁平对象所以足够，复杂模型需要逐层策略。

## 答案与思路

### 练习一

Array<StudyTask> 是当前数组；Promise<StudyTask[]> 是未来可能成功得到数组、也可能失败的异步结果。

### 练习二

    type A = Pick<StudyTask, "title" | "completed">;
    type B = Omit<StudyTask, "id" | "subject">;

### 练习三

    function getErrorMessage(error: unknown): string {
      return error instanceof Error ? error.message : "未知错误";
    }

### 练习四

使用 status 字面量作为共同判别字段，并只在对应分支放 task 或 message。

### 练习五

泛型保留类型之间的关系，实用类型从完整模型生成特定用途的结构，类型缩小让 unknown 在证据充分后安全使用。服务接口把页面需要的能力与存储技术分开，为 React、测试和未来 Tauri 实现建立稳定边界。
